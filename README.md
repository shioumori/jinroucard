# 夜明け前

スマートフォンのブラウザーで遊ぶ、ワンナイト人狼ベースのリアルタイム対戦ゲームです。Node.jsの標準機能だけで動き、追加パッケージはありません。

## ローカルで起動

Node.js 20以降を用意し、このフォルダーで実行します。

```sh
node server.js
```

ブラウザーで `http://localhost:8080` を開きます。同じWi-Fi内の端末からは、起動したPCのローカルIPアドレスとポート8080で接続できます。

## インターネットで遊ぶ

このプロジェクトにはRender Blueprint（`render.yaml`）を用意しています。HTTPS付きのNode.js Web ServiceをDockerで作成し、`/health`で稼働状態を確認します。

1. このプロジェクトをGitHubリポジトリにpushします。
2. RenderでBlueprintを作成し、そのGitHubリポジトリを接続します。
3. Renderが`render.yaml`を読み込み、デプロイ後に`https://<サービス名>.onrender.com`を発行します。
4. 参加者は同じURLを開き、ホストの部屋コードに参加します。

Blueprintは無料プランで試せる設定です。無料Web Serviceは15分間アクセスがないとスリープし、再アクセス時に起動まで約1分かかる場合があります。また、このゲームの部屋とスコアはメモリ内にあるため、再起動やスリープで消えます。1サービス・1インスタンスの短い試合で動作確認する用途です。安定した継続運用では常時起動プランを使い、長期スコアを保存する場合は共有データベースを追加してください。

Renderの制限：[無料インスタンス](https://render.com/docs/free) ／ [Blueprint](https://render.com/docs/infrastructure-as-code)

## 乱数と秘密情報

- 役職は設定枚数を満たす山札から暗号学的にシャッフルし、参加者に配り、残り2枚を墓場にします。
- 各プレイヤーにカード8種類から異なる3枚を暗号学的に選んで配ります。プレイヤー間では同じカードが重複して配られることがあります。
- カードは自分が提出するまで本人だけに見えます。提出者と役職は最終結果まで他の参加者に送信しません。自己開示の証明が成立した場合は、証明者の名前を公開します。
- 人狼・大狼の仲間情報、大狼の墓場、占い結果、各自の手札は参加者本人向けのイベントストリームにだけ送ります。サーバー側で行動・カード・投票・勝敗を検証します。
- 朝の会議と最後の会議には、部屋の参加者だけが見られるリアルタイムテキストチャットがあります。
- ホストはロビーで朝と最後の会議の時間をそれぞれ30秒〜10分に設定できます。時間切れになると次のフェーズへ進みます。全員が早く確認した場合もすぐ進みます。
- 各プレイヤーは試合中に「自分の記録を確認」から自分の夜の行動、手札、提出カード、個別のカード結果を見返せます。占い結果と吸血鬼の交換相手・交換結果は本人に表示します。
- 自己開示は元の役職が人狼・大狼の場合は選択・提出できません。サーバーでも使用を拒否します。

## ゲームルールの実装上の決め

- 夜の同時行動は、役職確認後に各自が選び、占い師、吸血鬼、医者の順に解決します。同じ役職の行動は席順です。通信の早さで結果が変わらないようにしています。
- 医者はプレイヤーを村人にするか「休診」を選びます。吸血鬼は他プレイヤーまたは墓場1枚目・2枚目と交換できます。
- 救世主は全参加者の過半数が提出すると、席順で最初に見つかった現在の人狼・大狼への票に1票を加えます。シャドウは現在の人狼・大狼・狂人が全員出すと、その人狼への票を1票減らします。
- 全プレイヤーの得票数が同じなら平和村判定です。人狼・大狼がいれば人狼陣営、いなければてるてる・狂人以外のプレイヤーが勝ちます。通常の最多票がプレイヤー同士で同数なら全員を処刑し、平和村とプレイヤーが同票で、全員同数ではない場合はプレイヤーの処刑を優先します。
- 勝者側の各プレイヤーに1ポイントを加算します。てるてるが単独勝利した場合は、てるてるに1ポイントを加算します。
- 人狼・大狼が両方いる場合、「現在の人狼」を対象にするカードは席順で最初に見つかった人狼または大狼を対象にします。

## テスト

```sh
node --test
```

役職枚数、シャッフル、各自3枚の手札、夜行動の解決順、カード条件、平和村判定、およびHTTP/SSEでの複数参加者の試合進行と秘密情報の分離を確認します。

GitHub Actionsでもpushとpull requestごとに同じテストを実行します。
